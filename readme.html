Screens

Tab-free shell: one Home page (the courses page) with everything else hanging off it — Profile is a sheet behind the avatar in the header, and the Explore catalog / course detail push onto the home navigation stack. On a fresh launch the app routes once: cards due → straight into the top-due review session (TikTok-style, no interstitial); nothing due but a course left unfinished → back into that course's session; otherwise it rests on Home. Closing a session always lands back on Home.

Data model

TableDescription
coursesTop-level course records. Stores generated curriculum as curriculum jsonb. Owner-scoped RLS. Soft-deleted via deleted_at. is_live (default false, toggled from the admin course list) controls whether the iOS app lists the course.
cardsOne row per renderable script section and per flashcard question (segment_key: intro, L1-S1, L1-S1-Q1, …). Holds video_r2_key, Whisper captions, and metadata.production (narration audio, visual board, prompts, alternate answers, cost ledger) for resumable generation. Question rows are the FSRS cards the app reviews. (Renamed from concepts.)
course_enrollmentsOne row per (user, course). Content progression is strictly linear (intro → L1-S1 → its questions → L1-S2 → …), so cursor_segment_key fully encodes which segments are watched. Also carries per-user knobs: desired_retention (default 0.90) and new_segments_per_session (default 2 — currently ignored by the app while sessions run uncapped).
card_statesPer-user FSRS memory state, one row per (user, question card): state (new/learning/review/relearning), due, stability, difficulty, reps, lapses, plus a scheduler version stamp (fsrs5-binary). Created lazily when the parent segment's video is completed. Partial index on (user_id, course_id, due) powers the "what's due" query.
review_logsAppend-only answer history: rating (1 = wrong/Again, 3 = right/Good), chosen answer, before/after memory state, elapsed days, and answer duration. Powers stats and future per-user FSRS parameter fitting — card state can be replayed from it under a new scheduler version.

Spaced repetition

The iOS app runs a binary FSRS-5 scheduler on device: a correct multiple-choice answer maps to Good (3), an incorrect one to Again (1) — Hard/Easy are never emitted, a supported degenerate case of FSRS using the stock default weights. Each answer updates stability/difficulty and reschedules due at the enrollment's desired retention (0.90). Wrong answers requeue in ~10 minutes (same session); review lapses move cards to relearning. A session = due reviews first (oldest due), then new segment videos each followed by its questions, with remaining reviews interleaved between the blocks; a client-rendered "LEVEL N" interstitial precedes each lesson's first new segment (presentational only — no cursor or FSRS impact). Sessions are currently uncapped — no review limit and every remaining segment is queued (new_segments_per_session is ignored) — an engagement experiment to measure how many videos people watch in one sitting. Every answer persists incrementally (card_states upsert + review_logs insert), so quitting mid-session loses nothing.

Workflow

1. New courseEnter a subject name (e.g. ancient greece), pick a curriculum model (Claude Fable / Opus 4.8 Fast / Sonnet 4.6 / GPT-5.5), and optionally a cover image URL.
2. Generate courseThe chosen model builds a full curriculum JSON, saves it to Supabase, and opens the studio.
3. Generate allOne button at the top fills in everything missing — cover, segment videos, captions, question videos — after a confirmation popup with a line-item cost breakdown (see below). The job runs server-side (POST /api/generate-all) and survives page reloads; the studio polls its progress and re-attaches on load. Or generate per card:
3b. Generate videoPer script section — one button runs the full 5-stage pipeline (audio → board → prompt → video → captions, below).
4. Question videosPer flashcard question — short clip + 6 alternate answers for spaced repetition.
5. PreviewRemotion Player overlays TikTok-style captions on the generated video, right on the card.

Production pipeline (per script section)

Each stage persists to cards.metadata.production. Generate video runs the full flow but only creates what's missing — cached audio, board, and video prompt are reused as-is; the video itself always generates. A single Redo toolbar on each card (↻ Audio / ↻ Board / ↻ Prompt / ↻ Captions) force-regenerates one part; regenerating audio or board clears the stored video prompt (it quotes the script verbatim and references board panels), so the next run rewrites it. The stage bar (Audio → Board → Prompt → Video → Captions + running cost) updates live through the whole flow. Seedance rejects generations as "too sensitive" (E005); controlled experiments (scripts/flag-experiment.mjs, scripts/face-experiment.mjs) reverse-engineered the filter: prominent photorealistic human faces in the reference board image are the #1 trigger (deepfake screening) — the prompt text is innocent even when it quotes scripts about wars verbatim. The board designer therefore only allows people as small, distant, indistinct figures. Timing is diagnostic: a flag within ~15s is the input scan (fix the board → ↻ Board); a flag after minutes is a stochastic output scan, which retries beat — the video stage auto-retries up to N times per click (default 4, via the Video retry policy control) with inputs frozen. Each card has an expandable Production details panel showing the narrated script, board image prompt, and Seedance video prompt (with copy buttons); it auto-opens on a video rejection so the offending prompt can be inspected.

Cost tracking: every segment keeps a cumulative spend ledger (metadata.production.costs) — shown as a green badge on the card with an audio/board/video breakdown in Production details. OpenRouter costs are exact (read from each response); Replicate costs come from rate constants in lib/production.ts: Seedance bills $0.08 per output second → $1.20 per 15s video (observed; blocked generations aren't charged), while Kokoro audio is measured GPU seconds × rate and lands around a tenth of a cent — effectively free. Retries and regenerates keep adding — the badge answers "what has this video cost so far". The Generate all confirmation popup itemizes the estimated spend before anything runs, one line per cost component: segment videos (Seedance 15s, ~$1.20 each), question videos (Seedance ~5s, ~$0.40 each), visual boards and the course cover (GPT Image, ~$0.30 / ~$0.25), and the LLM calls for board designs, video prompts, and alternate answers (~$0.05 per item) — plus zero-cost lines for Kokoro narration audio and local Whisper captions, and a green estimated total.

StageWhat happens
1. AudioKokoro-82M TTS (bm_george, speed 1.0 — natural storytelling pace) narrates the script. If the WAV runs over 15.00s, an LLM trims the script (given the current length) and audio regenerates — up to 4 trim passes. Saved as {segmentKey}.wav.
2. Visual boardAn LLM designs a 2×2 "Visual Production Board" — labeled reference panels (characters, places, objects) in one cinematic style — rendered by openai/gpt-5.4-image-2 via OpenRouter. The design prompt hard-bans weapons, blood, and combat imagery (a single visible weapon on the board trips Seedance's input filter). Saved as {segmentKey}-board.png.
3. Video promptAn LLM writes the Seedance prompt in a clearly-labeled structure — OVERVIEW: a 2-3 sentence prose summary of the video's mood and arc, SHOT LIST: a timestamped 0:00–0:15 shot guide referencing board panels, then NARRATION: the script quoted verbatim and tied to the reference audio file, plus music and ambience lines. The headers spell out which text is the visual guide vs. the spoken voiceover so the model never blends them. Stored on the segment; reused until ↻ Prompt or an upstream regen clears it.
4. VideoSeedance 2.0 (15s · 480p · 9:16 · seed 99) renders the stored prompt with the narration as reference_audios and the board as reference_images. Saved as {segmentKey}.mp4.
5. CaptionsWhisper.cpp transcribes the fresh video automatically after every render; word-level captions land on the cards row and the studio preview switches to the Remotion caption overlay. Re-run anytime via ↻ Captions.

Spaced-repetition question videos

Each flashcard question under a segment gets its own short clip via Create video on the question card: Kokoro narrates the question, the clip length is the audio duration rounded up to the whole second (so a 5.5s question becomes a 6s video; Seedance's minimum is 4s), and an LLM generates 6 alternate (wrong) answers stored on the question row for the app to rotate through. The video reuses the parent segment's board as its reference image (Seedance requires one with reference audio) and renders an unresolved, curiosity-building scene that never reveals the answer. Same retry policy and cost ledger as segment videos.

Curriculum JSON

Stored on courses.curriculum. Generated by a structured LLM prompt — no manual description field.

FieldDescription
title / subtitle / descriptionCourse metadata (description is model-generated scope line).
intro24–30 word pure-subject hook — one specific curiosity gap, second-person stakes, last line opens a loop chapter 1 pays off. No branding (the brand video is produced manually, outside generation). One script, no questions.
outline2–4 story acts with summaries and chapter titles (legacy field names: level_1_unit = act title, child_units = its chapters in order).
lessons[]10–12 chapters telling one continuous begin-to-end story (hard cap 40 segments ≈ $110/course). Each has 3–5 segments (24–30 word scripts at natural narration pace), each with 0–2 standalone flashcard questions (≤3-word answers, 4–6 per chapter). Question-less segments are continuation beats — multiple videos play back-to-back before the quiz. Legacy courses with level/parent_unit tree fields still render.
