Screens

Tab-free shell: one Home page (the courses page) with everything else hanging off it — Profile is a sheet behind the avatar in the header, and the Explore catalog / course detail push onto the home navigation stack. On a fresh launch the app routes once (LaunchRouter): dive straight back into the course you last worked on (most-recently-studied enrollment that still has due cards or unwatched content), skipping fully-finished courses; nothing studied yet → rest on Home. The session itself decides reviews-vs-lesson. Closing a session always lands back on Home.

ScreenDescription
Sign inSign in with Apple → Supabase session. All content is gated behind auth.
HomeInline header (avatar → Profile sheet, time-of-day greeting), a four-stat bar — day streak, cards due now, 30-day retention % over review-state answers, and learner Level (Explorer → Master, derived from cards in long-term memory) — with a "N of M cards in long-term memory" progress bar + %, a Review Due Now hero card ("N cards waiting", launches the session directly), an Explore Courses section with filter chips (For You / Languages / History / Science / Math / Tech) over horizontal course cards (cover, card count, progress), and a grouped My Courses list with progress % and red due-count badges.
ExploreFull catalog, pushed from the Explore section's "See all": pinned category chips + always-visible search over an endlessly scrolling two-column grid of course cards (cover, title, card count — no progress; browsing only). My Courses has no see-all page — the home list is the whole thing.
Profile sheetAccount identity, level, streak/memory/retention stats, and sign out. Opened from the avatar in the Home header.
Course detailSubtitle/description, watch progress from the enrollment cursor, outline, due-count badge, and Start/Continue learning.
SessionOne course, walked as an ordered list of blocks by the SessionCoordinator: (1) an opening live voice review (see below) of every due card, uncapped — skipped if nothing's due; then (2) for each section (a run of 1–3 segment videos ending at the one that carries questions) a teaching feed block immediately followed by a review block scoped to just that section's just-watched cards. The feed is a full-screen 9:16 player of intro → new segment videos in order, with TikTok-style word captions; a SwiftUI-rendered level interstitial plays before each lesson's first new segment — "LEVEL N" + lesson title cascade in letter-by-letter on pure black, hold, fade out — and the feed crosses it by fading through black (video fades to black → letters play → next video fades in from black) instead of the usual scroll. The feed never quizzes; watching a section registers its question cards as new/due-now and the very next block reviews them. A summary screen closes it out.
Live voice reviewA spoken conversation with a Gemini Live voice agent that conducts spaced repetition (both first reviews and repeats). A calm Nano Banana still backdrop (one per card, cross-faded as the agent advances) sits under a voice UI — talk indicator, live transcript, mute, progress. The agent asks each question aloud, hears the spoken answer over the mic, judges it, and emits a semantic assessment; the device maps that to an FSRS Again/Hard/Good/Easy rating, runs the on-device scheduler, and persists each grade through the submit-grade Edge Function. Nothing on screen reveals the answer. The opening review grades the whole due queue; each section's immediate review is scoped to just the cards from the section just watched. When a review block's queue clears the agent gives a short wrap-up and the coordinator advances to the next block.

Data model

TableDescription
coursesTop-level course records. Stores generated curriculum as curriculum jsonb. Owner-scoped RLS. Soft-deleted via deleted_at. is_live (default false, toggled from the admin course list) controls whether the iOS app lists the course.
cardsOne row per renderable script section and per flashcard question (segment_key: intro, L1-S1, L1-S1-Q1, …). Holds video_r2_key, Whisper captions, and metadata.production (segment narration audio, visual board, video prompts; question review-image prompt + still key; cost ledger) for resumable generation. Question rows are the FSRS cards the voice agent reviews. (Renamed from concepts.)
course_enrollmentsOne row per (user, course). Content progression is strictly linear (intro → L1-S1 → L1-S2 → …), so cursor_segment_key fully encodes which segments are watched. Also carries per-user knobs: desired_retention (default 0.90) and new_segments_per_session (default 2 — currently ignored by the app while sessions run uncapped).
card_statesPer-user FSRS memory state, one row per (user, question card): state (new/learning/review/relearning), due, stability, difficulty, reps, lapses, plus a scheduler version stamp (fsrs5). Created lazily (due now) when the parent segment's video is completed, then graded by the voice agent. Partial index on (user_id, course_id, due) powers the "what's due" query. A composite FK on (user_id, course_id) → course_enrollments means deleting an enrollment cascades away that course's card states (and, via review_logs.card_state_id, its review history) — leaving/resetting a course wipes its progress in one delete.
review_sessionsOne row per voice review session: course_id, scheduler, status (active/completed/abandoned), card_count, and the agent's qualitative end-of-session report jsonb (overall / strengths / weaknesses / focus_next). Created by start-review-session, finalized by finish-review-session. Owner-scoped RLS.
review_logsAppend-only grade history: session_id, source (always voice), full FSRS rating (1 Again / 2 Hard / 3 Good / 4 Easy), the agent's semantic assessment (correct/partial/incorrect/skipped) + agent_rationale + optional answer_transcript, before/after memory state, and elapsed days. Powers stats and future per-user FSRS parameter fitting — card state can be replayed from it under a new scheduler version.

Spaced repetition

Review is conducted entirely by the live voice agent — there is no multiple-choice path. The agent judges each spoken answer and emits a semantic assessment; the device maps it to the full FSRS-5 Again/Hard/Good/Easy scale (the mapping lives in app code, not the prompt: incorrect/skipped → Again, partial → Hard, correct → Good, correct-and-fluent → Easy, correct-with-hint → Hard) and runs the scheduler on device. Each grade updates stability/difficulty and reschedules due at the enrollment's desired retention (0.90); review lapses move cards to relearning. A session opens with the voice review of every due card — including new cards getting their first review — uncapped; then it teaches new content one section at a time, and the moment a section's videos finish the voice agent immediately reviews that section's just-watched cards before moving on (a client-rendered "LEVEL N" interstitial precedes each lesson's first new segment, presentational only). So watching a section registers its question cards as new/due-now and the very next block grades them — review always happens before the next new content. Sessions are uncapped (new_segments_per_session is ignored) — an engagement experiment. Each grade persists incrementally through the submit-grade Edge Function, so quitting mid-session loses nothing.

Edge Functions

Deno functions in supabase/functions/ back the live voice review; shared helpers live in _shared/lib.ts.

FunctionDescription
start-review-sessionOpens a review_sessions row, builds the due queue for a course — cards whose due has passed, including state = 'new' first reviews — as a manifest of { cardId, question, answer, reviewImageUrl }, and mints a short-TTL ephemeral Gemini Live token (from the server-side GEMINI_API_KEY function secret) so the device never holds a long-lived key. Accepts an optional cardIds[] to scope the manifest to exactly those cards — the app passes it for a section's immediate review and omits it for the opening all-due review. Returns { sessionId, token, model, manifest }.
submit-gradePersists one graded card: validates the FSRS rating + assessment, writes the card_states upsert and the review_logs row (source = 'voice'), and grades new cards as well as due reviews.
finish-review-sessionCloses the session — marks review_sessions.status completed/abandoned and stores the agent's qualitative end-of-session report.

aretay-admin

The AI course-generation + video-production studio. It now lives inside the unified aretay-web repo and is served at /admin. The whole admin surface (/admin + all /api/* routes) is local-only: proxy.ts returns 404 for those paths unless ADMIN_ENABLED=true, which is set only in local .env.local (and by run-admin.sh). The deployed site leaves the flag unset, so aretay.ai exposes only the public marketing pages (/, /privacy.html, /support.html) — no auth needed because the admin simply doesn't exist in production. Generation still runs on your machine (it needs the local whisper.cpp binary, ffmpeg, and Remotion rendering).

2. Generate courseThe chosen model builds a full curriculum JSON, saves it to Supabase, and opens the studio.
3. Generate allOne button at the top fills in everything missing — cover, segment videos, captions, review images — after a confirmation popup with a line-item cost breakdown (see below). The job runs server-side (POST /api/generate-all) and survives page reloads; the studio polls its progress and re-attaches on load. Or generate per card:
3b. Generate videoPer script section — one button runs the full 5-stage pipeline (audio → board → prompt → video → captions, below).
4. Review imagePer flashcard question — one editable image prompt + a Nano Banana still backdrop for the live voice review.
5. PreviewRemotion Player overlays TikTok-style captions on the generated video, right on the card.

Production pipeline (per script section)

Each stage persists to cards.metadata.production. Generate video runs the full flow but only creates what's missing — cached audio, board, and video prompt are reused as-is; the video itself always generates. A single Redo toolbar on each card (↻ Audio / ↻ Board / ↻ Prompt / ↻ Captions) force-regenerates one part; regenerating audio or board clears the stored video prompt (it quotes the script verbatim and references board panels), so the next run rewrites it. The stage bar (Audio → Board → Prompt → Video → Captions + running cost) updates live through the whole flow. Seedance rejects generations as "too sensitive" (E005); controlled experiments (scripts/flag-experiment.mjs, scripts/face-experiment.mjs) reverse-engineered the filter: prominent photorealistic human faces in the reference board image are the #1 trigger (deepfake screening) — the prompt text is innocent even when it quotes scripts about wars verbatim. The board designer therefore only allows people as small, distant, indistinct figures. Timing is diagnostic: a flag within ~15s is the input scan (fix the board → ↻ Board); a flag after minutes is a stochastic output scan, which retries beat — the video stage auto-retries up to N times per click (default 4, via the Video retry policy control) with inputs frozen. Each card has an expandable Production details panel showing the narrated script, board image prompt, and Seedance video prompt (with copy buttons); it auto-opens on a video rejection so the offending prompt can be inspected.

Cost tracking: every segment keeps a cumulative spend ledger (metadata.production.costs) — shown as a green badge on the card with an audio/board/video breakdown in Production details. OpenRouter costs are exact (read from each response); Replicate costs come from rate constants in lib/production.ts: Seedance bills $0.08 per output second → $1.20 per 15s video (observed; blocked generations aren't charged), while Kokoro audio is measured GPU seconds × rate and lands around a tenth of a cent — effectively free. Retries and regenerates keep adding — the badge answers "what has this video cost so far". The Generate all confirmation popup itemizes the estimated spend before anything runs, one line per cost component: segment videos (Seedance 15s, ~$1.20 each), review images (Nano Banana still, ~$0.067 each) and their image-prompt LLM call (~$0.01 each), visual boards and the course cover (GPT Image, ~$0.30 / ~$0.25), and the LLM calls for board designs and video prompts (~$0.05 per segment) — plus zero-cost lines for Kokoro narration audio and local Whisper captions, and a green estimated total.

StageWhat happens
1. AudioKokoro-82M TTS (bm_george, speed 1.0 — natural storytelling pace) narrates the script. If the WAV runs over 15.00s, an LLM trims the script (given the current length) and audio regenerates — up to 4 trim passes. Saved as {segmentKey}.wav.
2. Visual boardAn LLM designs a 2×2 "Visual Production Board" — labeled reference panels (characters, places, objects) in one cinematic style — rendered by openai/gpt-5.4-image-2 via OpenRouter. The design prompt hard-bans weapons, blood, and combat imagery (a single visible weapon on the board trips Seedance's input filter). Saved as {segmentKey}-board.png.
3. Video promptAn LLM writes the Seedance prompt in a clearly-labeled structure — OVERVIEW: a 2-3 sentence prose summary of the video's mood and arc, SHOT LIST: a timestamped 0:00–0:15 shot guide referencing board panels, then NARRATION: the script quoted verbatim and tied to the reference audio file, plus music and ambience lines. The headers spell out which text is the visual guide vs. the spoken voiceover so the model never blends them. Stored on the segment; reused until ↻ Prompt or an upstream regen clears it.
4. VideoSeedance 2.0 (15s · 480p · 9:16 · seed 99) renders the stored prompt with the narration as reference_audios and the board as reference_images. Saved as {segmentKey}.mp4.
5. CaptionsWhisper.cpp transcribes the fresh video automatically after every render; word-level captions land on the cards row and the studio preview switches to the Remotion caption overlay. Re-run anytime via ↻ Captions.

Spaced-repetition review images

A flashcard question card needs only its question + answer (already in the curriculum) and one still backdrop for the live voice review — no Kokoro/Seedance clip, no alternate answers. Generate review image runs two steps: an LLM writes an editable image prompt (stored on the question row, regenerable from the studio), then google/gemini-3.1-flash-image-preview (Nano Banana 2) renders one PNG still, using the parent segment's board — or the course cover — as a style reference for visual continuity. The prompt aims for dual coding: a vivid, distinctive visual anchor for the idea being reviewed that pairs with the spoken Q&A and gives the voice tutor something to point at, without depicting the literal answer token. The voice agent grades the spoken answer against the canonical answer generically — there is no per-question rubric. Spend books to the question card's cost ledger like any other card.
